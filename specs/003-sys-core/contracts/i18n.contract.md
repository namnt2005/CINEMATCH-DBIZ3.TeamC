# Contract: bilingual display dictionary (FR-005, FR-006, US-3)

Feature: `003-sys-core` · Decisions: D7, [research.md](../research.md) R10, Open question 7

## Files

`messages/vi.json`, `messages/en.json`: flat objects, dotted keys (`signup.title`, `common.no_data`), string values, `{name}` placeholders. Both files have exactly the same keys.

## API

- `t(key, vars?)` server-side (`lib/i18n/server.js`, locale from the request) and client-side (`useT()` from `lib/i18n/client.js`, locale from the provider).
- `getLocale()`: cookie `locale` (`vi` | `en`); otherwise the first supported language of `Accept-Language`; otherwise `vi`.
- `setLocale(locale)` (client): writes the cookie (1 year, `SameSite=Lax`), saves `profile.locale` for a signed-in user (`PATCH /api/account`), then `router.refresh()` — no full reload, so the scroll position stays (US-3 Scenario 1).

## Build check — FR-006 *missing key fails the build*

`node scripts/check-i18n.mjs` (run by `npm run prebuild` and by a unit test) fails when:

1. a key exists in one file and not the other;
2. a key used in the code (`t('…')`, `useT()('…')`) is missing in either file;
3. a value is empty.

## Screens moved to the dictionary (D7)

SYS screens SC-04, SC-06, SC-07, SC-08, SC-09, SC-42, SC-43, the shared header (language switch, sign-in state, notification badge), and the built screens SC-14, SC-15, SC-16, SC-35. A unit test scans these files for user-visible text outside `t()` (letters inside JSX text nodes or `label`/`placeholder`/`title`/`aria-label` attributes).
