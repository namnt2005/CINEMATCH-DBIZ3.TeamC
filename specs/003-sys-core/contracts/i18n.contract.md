# Contract: bilingual display dictionary (FR-005, FR-006, US-3)

Feature: `003-sys-core` · Decisions: D7, [research.md](../research.md) R10, Open question 7

## Files

`lib/i18n/vi.json`, `lib/i18n/en.json` (moved from `messages/`, Nam Tran 02/11/2026): flat objects, dotted keys (`signup.title`, `common.no_data`), string values, `{name}` placeholders. Both files have exactly the same keys.

## API

- `t(key, vars?)` server-side (`getI18n()` in `lib/i18n/server.js`, locale from the request) and client-side (`useT()` from `lib/i18n/client.js`, locale and messages passed by the server page to `<I18nProvider>`, so the browser never loads both dictionaries). Shared pure helpers in `lib/i18n/index.js`.
- API error bodies carry the English text (`apiMessage`); screens show the user's language from the error `code`, and validation `fields` values are dictionary keys.
- `getLocale()`: cookie `locale` (`vi` | `en`); otherwise the first supported language of `Accept-Language`; otherwise `vi`.
- `setLocale(locale)` (client): writes the cookie (1 year, `SameSite=Lax`), saves `profile.locale` for a signed-in user (`PATCH /api/account`), then `router.refresh()` — no full reload, so the scroll position stays (US-3 Scenario 1).

## Build check — FR-006 *missing key fails the build*

`node scripts/check-i18n.mjs` (`npm run check:i18n`, run by `prebuild` and by `tests/unit/i18n-dictionary.test.js`; logic in `scripts/lib/i18n-check.mjs`) fails when:

1. a key exists in one file and not the other;
2. a key used in the code (`t('…')`, `useT()('…')`) is missing in either file;
3. a value is empty.
