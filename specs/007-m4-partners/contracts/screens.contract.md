# Contract: screens (SC-19, SC-20, SC-21, SC-22, SC-23, SC-25, SC-36 and two pages without a Screen Spec)

Feature: `007-m4-partners` · Screen Specs in `docs/screens/` are the contract; this file lists the build choices. All text through `lib/i18n` (vi, en); screens read the APIs of the other contracts or the same `lib/db/` functions on the server.

| Screen | Route | Who | Built from | Notes |
|---|---|---|---|---|
| SC-19 Partner directory | `/partners` | guest, signed in | `GET /api/partners` | 12 groups with counts (#3), province (#4), language for signed-in users only (#5, Open question 7), *VFDA Verified only* on by default (#6), card with initials instead of a logo (#7, Open question 10), badge + month (#8), member line hidden for guests (#10), *Send request* → SC-04 for guests, SC-23 otherwise (#11), *Not verified* when #6 is off (#12), explainer (#13, draft wording, Open question 5); filters in the URL |
| SC-20 Partner profile | `/partners/[slug]` | guest, signed in | `GET /api/partners/:slug` | three blocks in the order of the layers; the locked private layer shows *opens after an accepted request and the NDA of both sides* (#11); three-layer indicator from `layers` (#12); *What VFDA checked* with the *not checked* line (#10); Article 13 badge with *not legal advice* (#6); *View request* instead of *Send* when `my_request` is open (#13); *No longer active* for a deactivated organisation |
| SC-23 Send collaboration request | `/partners/[slug]/request` | producer (owner / edit) | `POST /api/requests` | non-archived projects only (#4); project summary (#5); organisation's groups first (#6); note counter 1000 (#7); Article 13 notice when not eligible (#8, SR-345); *What happens next* (#9); errors for an open request or a deactivated organisation |

| SC-21 My organisation | `/partners/me` | partner | `GET/PATCH /api/partners/me` | three sections labelled with who can see them (SR-321); 12-group chips (#6); provinces (#7); languages (#10); portfolio as text lines that describe the work without project titles (SR-132, Open question 14), no photo upload (#11, Open question 10); rate card table (#12); *Preview as* Guest / Member / Accepted (#15) built from the same layer shaping as SC-20; *Save* enabled only when changed and #4–#7 valid (#17); deactivate with the typed name (#18); badge and Article 13 read-only (SR-326); no *Pending review* label in this slice (D3) |

| (no Screen Spec) Invite a partner | `/admin/partners/invite` | `vfda_staff`, `admin` | invitations API | organisation public fields + email; list of invitations and their state (Open question 9) |

Navigation added: header *Đối tác / Partners* → `/partners` (everyone); *Tổ chức của tôi / My organisation* → `/partners/me` and *Yêu cầu / Requests* → `/requests` (role `partner`); *Xác minh đối tác* → `/admin/verification` and *Mời đối tác* → `/admin/partners/invite` (staff / admin); project sidebar *Đối tác / Partners* → `/requests?project=<id>`.

Phone width 360 px: lists stack, filters fold into a panel; status is text, not colour alone.
